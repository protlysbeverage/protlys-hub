# Frontend design — Protlys adaptation

- Start with the product, audience, task, and the existing Protlys design system. The root `DESIGN.md` already supplies the visual direction; do not repeat discovery or invent a new brand.
- Use the established green palette, Plus Jakarta Sans / Manrope / Space Grotesk typography roles, supplied logo, dark/light themes, and five-destination navigation.
- Build from task hierarchy, content density, responsive composition, and meaningful states—not a stock hero-plus-cards template.
- Do not introduce reflex palettes, random display fonts, gradients, glassmorphism, ornamental grids, or decorative animation.
- For genuinely new surfaces, state the design intent and signature detail before implementation. Keep it consistent with Protlys rather than copying a reference product.
- Audit the rendered interface for hierarchy, responsive fit, readable type, contrast, keyboard focus, touch targets, and reduced motion.

This skill complements, but does not replace, the more complete `better-design` workflow. It must never override existing approved Protlys tokens.
